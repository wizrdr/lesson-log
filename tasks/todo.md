# Lesson Log — план реализации

Источник идеи: карточка «Lesson Log» в прожарке «Десять выживших» (05.09.2026).
Решения 05.09: код сразу, без фазы разговоров; первые пользователи — Максим и жена; код пишут агенты, Максим ревьюит и проверяет на реальных уроках.

## Что строим (v1 для двух пользователей)

Студент загружает запись урока с репетитором → транскрипт → LLM вытаскивает исправления, новые слова и правила в накопительный журнал → карточки SRS до следующего урока → экран «перед уроком» с открытыми ошибками.

**Не в v1:** захват вкладки Zoom из браузера, push, share-ссылка репетитору, оплата, лендинг. Всё это появляется только после двух недель реального использования вдвоём.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Ввод аудио | Только загрузка файла: `audio_only.m4a` из локальной записи Zoom, Voice Memos с iPhone для очных уроков | getDisplayMedia со звуком работает только в Chrome на десктопе, iPhone во время звонка не пишет вообще. Загрузка покрывает оба кейса без хаков |
| Транскрипция | **Deepgram Nova-3 (`language=multi`) с callback**, Whisper как запасной вариант; решается спайком | Whisper API режет файлы >25 МБ (час m4a ≈ 30–60 МБ) и плохо держит смесь PL/RU. Deepgram берёт файл по signed URL до 2 ГБ и сам дёргает наш webhook, Edge Function не упирается в лимит 150 с |
| Извлечение | Claude Sonnet 5, structured output по JSON-схеме `{type, original, corrected, rule, quote}` | Точность важнее цены: ошибочные карточки убивают доверие. Haiku 4.5 сравнить в спайке |
| Аудио после обработки | Удаляется, хранится только транскрипт | Supabase Storage free = 1 ГБ ≈ 20 уроков. Плюс приватность |
| Данные на клиенте | Обычный Supabase + RLS, без Dexie-синка | Пайплайн серверный по природе, local-first ничего не даёт двум пользователям и добавляет слой синка |
| SRS | `ts-fsrs` | Готовый FSRS, свой алгоритм писать незачем. В Dayline SRS нет, переиспользовать нечего |
| Из Dayline берём | токены `tokens.css` + примитивы `src/ui`, magic-link auth, каркас Edge Functions, PWA-конфиг, деплой на GitHub Pages, позже функцию `remind` (web-push уже есть) | Личный код, правило «без рабочего кода» не нарушается |
| Стек | React 19 + Vite + TS + Tailwind v4, Supabase (Postgres, Auth, Storage, Edge Functions), GitHub Pages | Тот же, что в Dayline: агенты уже знают конвенции |
| Где Supabase | Схема `lesson_log` в проекте dayline (ref ghuhochssdbzyxextlso), Edge Functions с префиксом `ll-`, миграции через `db push --include-all` | Free-тариф: два активных проекта уже заняты (dayline, calibrator). Пользователи те же, auth общая. Решение 05.09 |
| Согласие репетитора | Чекбокс «репетитор предупреждён» на каждого репетитора, один раз | Запись без согласия — юридический и этический риск |

## Модель данных

- `tutors` — id, user_id, name, language (`pl`/`en`), consent_at
- `lessons` — id, user_id, tutor_id, date, audio_path (nullable после обработки), transcript, status (`uploaded` → `transcribing` → `extracting` → `ready` / `failed`), error
- `entries` — id, lesson_id, user_id, type (`correction` / `vocab` / `rule`), original, corrected, explanation, quote, deleted_at
- `cards` — entry_id, FSRS-поля (`due`, `stability`, `difficulty`, `reps`, `lapses`, `state`), last_review
- RLS: всё по `user_id = auth.uid()`
- `cards` дублирует `user_id` вместо join на `entries`: политика остаётся одной строкой, индекс `(user_id, due)` отдаёт due-карточки без join, а пишет обе таблицы одна функция `ll-extract`, так что расхождение невозможно. FSRS-поля добавлены до полного `Card` из `ts-fsrs` (`elapsed_days`, `scheduled_days`, `learning_steps`), иначе карточку нельзя восстановить без потерь.
- Все таблицы в схеме `lesson_log` общего с Dayline Supabase-проекта (решение 05.09), storage bucket `audio` общий, путь `{user_id}/{lesson_id}.m4a`.

## Пайплайн

1. Клиент грузит файл в Storage `audio/{user}/{lesson}.m4a`, создаёт `lessons` со статусом `uploaded`.
2. Edge Function `transcribe`: signed URL → Deepgram с `callback=<url функции extract>`; статус `transcribing`.
3. Edge Function `extract` (webhook Deepgram): сохраняет транскрипт → Claude → `entries` + `cards` → статус `ready` → удаляет аудио.
4. Клиент подписан на `lessons` через Realtime, показывает прогресс.
